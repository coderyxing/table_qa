# 面向超越Chain-of-Table的改进方案与执行协议

日期：2026-11-06。目标是三任务质量指标均超过可核验的Chain-of-Table对照，同时减少学生在线成本；目标不是预先成立的结论。当前没有超过Chain-of-Table的正式测试证据。

## 1. 对照究竟是什么

已核验[ICLR 2024论文](https://proceedings.iclr.cc/paper_files/paper/2024/file/f53fd88a4340063ecd258c0ae9948b40-Paper-Conference.pdf)的算法1、表1、表6、附录C以及[作者代码](https://github.com/google-research/chain-of-table)。其流程包含逐轮选择操作、生成参数、执行更新表格、最终查询。五类操作包括语义增列。迭代反馈、多候选以及普通蒸馏都不能直接包装成本文首创。

论文表1的PaLM 2-S结果：WikiTQ 67.31%、TabFact 86.61%；GPT-3.5对应59.94%、80.20%。表6仅列PaLM 2：FeTaQA BLEU 32.61、ROUGE-1/2/L为0.66/0.44/0.56。这些是论文报告结果，尚未完成与本项目测试ID、预处理和评测实现的一一对齐。不得把小验证集分数直接填在同一可比测试表中。

设立两个独立比较层次：

- **同底座方法比较**：在同一Qwen检查点上移植作者动态规划、参数生成、五类操作、演示与最终查询；保存上游commit、许可证、逐项差异。原始参数配置与预算匹配配置分列。现有A3仍标为完整计划适配，不能改名为原版Chain-of-Table。
- **公开结果竞争力比较**：仅在测试ID、任务、指标和预处理核验后比较论文报告数字；跨模型/跨训练条件的结果只能说明系统竞争力。还需纳入已核验的后续强方法，超过2024年方法不等于当前SOTA。

作者仓库主入口使用旧OpenAI后端及Dater清洗映射；本地Qwen后端、原始/清洗表格差异均需披露。不能只移植操作名、取消演示/参数采样、缩短预算，再将其称为忠实复现。

## 2. 当前最值得先解决的瓶颈

已有600条训练开发中，32B直接回答优于当前受限操作接口；WikiTQ A4有85/200执行失败，包括上下文33、数值27。当前学生扩展池只有172个来源，且FeTaQA操作轨迹尚无人工批准。这些信息支持先补能力与数据，而不是立即增加训练轮数。

尤其要补齐与原方法的能力差异：现有derive主要支持算术，原方法能语义增列。只让执行器更严格，会拒绝更多程序，却不能自动得到正确程序。另有训练接受池TabFact标签偏斜、短链使状态分块几乎退化为固定分块、激进删链损害WikiTQ等已观察问题。

## 3. 候选创新一：问题条件约束与证据保留的语义可执行链

### 3.1 将题意条件显式绑定到程序

模型从问题生成结构化条件清单，每项包含问题原文跨度、约束类型、涉及列、比较/聚合范围以及对应操作编号。明确区分“至少一个”“全部”“仅有”“前/后”“并列最多”等范围和量词。跨度引用可机械核验；条件是否完整、列匹配是否正确仍需过程标注或人工抽查，不能声称纯规则证明自然语言题意。

令C(Q)为模型抽取且经过来源检查的条件集合，b(c)为条件到操作的绑定。在线接受约束为：

\[
\mathcal A(P)=I_{type}(P)I_{dep}(P)I_{bind}(P,C)I_{exec}(P).
\]

四个二值项分别验证类型/单位、读写依赖、条件是否有执行绑定、实际重放。I_bind不验证自然语言条件抽取完备性。记录“条件未提取”“绑定无效”“绑定正确但答案错误”三类，避免只看可执行率。

代码设计：新增contracts.py管理条件对象与检查器；inference.py在每块前检查未完成义务，删列/聚合前保护所需字段；保留原表及不可变快照，仅向模型暴露明确选择的证据视图。约束预测和检查成本均计入。

### 3.2 补齐可追溯语义派生与严格数值能力

两个互补支路。进一步固定源码核验发现：原add_column_act**已经有整列子串来源校验**，因此下列抽取能力不独立算创新，详见[复现差异核验](chain-of-table-reproduction-audit.md)：

- 显式数量：原值、来源单位、目标单位和换算规则都保留。禁止将日期范围、带脚注字符串直接去掉非数字字符。未知单位拒绝，不能默认0或悄悄删行。
- 语义派生：优先使用原单元格的字符跨度抽取，如“姓名(国籍缩写)”生成国籍列；校验跨度及复制值，记录当前格跨度和根单元格来源。归一化映射必须有明确规则/词典版本；自由生成的语义列单列为模型判断，不能伪称执行器已证明。这是能力补齐；论文新增贡献需要落在条件绑定与跨步骤保护，不能将原方法已有的子串检查换名。

数量换算公式为v_target=v_raw*s_scale*s_source/s_target，只在维度一致时成立。它用于混合单位比较和聚合，不是新的数学理论或单独创新。

**本轮已实现**quantities.py及quantity表达式：显式长度/质量/时长/比例/三种明确货币与thousand/million/billion；精确Decimal运算；非有限、非完整匹配、维度冲突及需要无限小数舍入的转换拒绝。无货币汇率转换、日期猜测或含糊美元符号推断。derive新增列，保留原值/lineage；来源单位仅在单元格没有单位时使用。默认提示与旧运行不变，新增typed_quantities开关。此组件是支撑工具，不单独声称创新或准确率已提升。

### 3.3 分离事实计算与答案表达

短答案先得到值/实体及来源，再允许受证据约束的表达归一化；例如缩写到完整实体名需要显式映射，不能把任意字面量答案当计算结果。FeTaQA先生成可溯源事实清单，再生成长答案并逐项对齐事实。

证据覆盖度Cov=|已覆盖的必要事实|/|标注必要事实|，无依据率Unsup=无证据原子陈述数/原子陈述总数。没有人工必要事实标注时不伪报Cov，自动来源对齐和人工事实评价分列。BLEU/ROUGE同时保留，不能用事实指标替代未提升的原有指标。

代码设计：semantic_columns.py、answer_realization.py及facts.py；只允许有来源的跨度/显式映射/执行输出进入事实集合，保留自由表达部分的未验证标记。两位独立真人审核FeTaQA，参考答案只用于训练监督和离线评测。

## 4. 候选创新二：条件保持的操作融合与状态反馈分块蒸馏

不再只用“当前表输出相同”作为删操作理由。先从方法一的条件绑定构造依赖图，再压缩表达、合并可证明可组合的子程序；必须保留每个问题条件、聚合范围、并列结果、来源及反馈边界。

融合块允许多个原子操作共享一次生成/执行交互，但内部保留有序原子计划和条件绑定。连续筛选不能未经证明改成无序AND：严格数值解析的异常路径、证据覆盖及短路行为也必须保持。最终操作数与原子操作数分别报告，不通过把八步改名为“一步”虚构效率。

\[
\min_{\tilde P,\mathcal B}\sum_{B\in\mathcal B} [\alpha T_{in}(S_B)+\beta T_{out}(B)+\gamma]
\quad\text{s.t. 条件/状态/来源/反馈约束保持}.
\]

T_in/T_out由实际tokenizer计算；alpha/beta/gamma是事先选定的代价权重或训练集测得的延迟模型参数。token代理和实测秒数分列。已有状态DP只能离线用于教师监督；测试时学生依据当前状态预测块终点，不接触未来教师链。

训练损失继续采用操作块和答案的交叉熵：L=L_block+lambda*L_answer。不要为了公式数量添加无法解释的新损失。增量部分应是条件保持约束、状态变化与反馈边界的联合监督，而不是普通LoRA/蒸馏本身。

代码设计：保留optimization.py激进搜索作为负向对照；新增condition_fusion.py及边界标注，修改distillation.py传递条件监督。若真实短链中分块无显著优势，应收缩贡献范围，不能人为往链里加冗余步骤制造加速。

## 5. 准确率支撑改进与训练路线

|优先级|改进|固定对照与主要风险|
|---|---|---|
|P0|恢复原方法的语义增列/最终查询能力，跑可信基线|同模型、同来源；先区分能力补齐与本文约束的增益|
|P0|严格类型/单位及问题条件绑定|工具开/关、约束开/关，报告拒绝率与误拒绝率；更严格不必然更准|
|P0|扩大并审核教师训练轨迹|接受量500→2000→5000为有界阶梯；每阶段检查收益后决定是否扩大，不预先承诺接受数量或耗时|
|P0|补FeTaQA事实与表达监督|实体、数值、比较和必要事实覆盖；双人审核、统一BLEU/ROUGE版本及尺度|
|P1|训练困难反例与最小修复|训练集上改变比较词/数量词/条件，重算程序结果并审核语义；原问题及变体整表隔离，不能自动假定改词后标签必翻转|
|P1|有限多候选与验证重选|K=1/2/4；不得看标准答案选候选。等token/调用预算比较，固定排序规则；加算力收益单列，不能单独当创新|
|P1|两阶段学生训练|先操作/类型/断言能力，再三任务联合与块监督；数据、预算与标签分布审计；3B主消融、7B质量上限|
|P2|风险触发的局部修复/回退|按执行失败、条件缺口、候选分歧触发；阈值只用允许的开发集，所有成本和回退无程序证据比例计入|

教师仍使用双A40的32B BF16，先生成再训练；学生3B/7B单卡LoRA。无需立即训练32B或叠加RL。已有[Table-R1](https://arxiv.org/abs/2505.23621)包含推理蒸馏与RLVR，这些已有路线不能直接冒充第三个原创点。已有[Effective Distillation](https://aclanthology.org/2024.lrec-main.492/)针对科学表到文本，不能未经任务对齐当作三任务直接基线。

## 6. 实验改成可判定的阶梯

1. 冻结可信Chain-of-Table移植和原版参数表；先在训练开发诊断能力差距，禁止用A3替代。
2. 同一32B教师接口按：能力补齐 → 加条件绑定 → 加来源机制 → 加有限修复；2×2约束/来源消融保留。换底座、扩池和多候选分别做控制。
3. 同一池、同一3B做B0/B1/B2/B3/B4/B5，等源ID与等目标token分表，3个种子。7B做关键组。不得把教师对学生的优势或额外训练量归因给结构模块。
4. FeTaQA补自动质量与人工事实评价，三任务都做主比较。方法一主要检验质量，方法二还检验相近质量的成本改善；所有核心指标如实保留。
5. 同GPU、精度、后端、输入、预热及重复测量效率，报告失败、修复、候选、路由、验证全部开销。画质量—延迟/token曲线，区分高质量配置和高效率配置。
6. 七类实验仍全部保留：主实验、比较、消融、泛化、参数、机制、案例。长链/混合单位/量词题是预定义子群，不替代全测试集。

对“全部超过”的验收，应预先列六项任务指标：WTQ denotation accuracy、TabFact accuracy、FeTaQA BLEU与R-1/R-2/R-L，并明确这些指标与额外机制指标的区别。逐项报告配对差值与区间；若声称同时显著超过，采用预先固定的多重比较控制（如六项单侧检验Holm校正）。仅点估计全部更高不等于统计上同时优越。ROUGE逐样本、BLEU语料级bootstrap必须分别正确计算，不能平均句子BLEU冒充语料BLEU。

方法二的质量非劣界限须在实验前按任务分数尺度设定并论证；不能看到下降后再放宽。如果用户目标是准确率也全部更高，则同时检验相对强基线的优越性，不能用“没显著下降”代替“提高”。

原200条调优及已评价的200条确认集均已使用。后续开发不能再称确认集未见；最终正式test只在方法/指标/配置冻结后统一运行。

## 7. 本轮落地与运行入口

- quantities.py：确定性单位解析与精确换算；core.py接入derive表达式并沿用依赖/来源。
- inference.py：settings.typed_quantities=true才暴露/允许新表达式，默认关闭；不读取参考答案。
- build-records --typed-quantities：训练与推理提示一致；状态DP以相同扩展提示计token。
- scripts/quantity_pilot.py：训练集、固定随机种子、逐表最多一题；含显式单位的8表机制诊断，单一32B实例交错比较，原表不变。不是完整基准，不能凭这个子集声称提分。
- 本机/GPU12当前140项测试通过。诊断独立代码位于服务器runs/quantity-candidate-v1/code，旧检查点、确认结果及旧运行不改写。

推理配置示例：在现有教师配置的settings加入"typed_quantities":true。训练记录构建另传--typed-quantities。完整运行须固定新代码哈希，并使用匹配提示重新生成的轨迹；旧学生并未因此自动学会新工具。

例：500 m与2 km通过quantity派生出0.5与2，原列保持不变，极值操作得到后者；2 kg与500 m同列时明确拒绝维度混淆。这是可执行能力示例，不是真实评测成绩。

### 首轮诊断已完成

服务器已完成每任务4条、共8条输入的双条件诊断。WTQ官方评测算法Python3端口为plain 0/4、quantity 1/4；TabFact均1/4；两组均6/8执行成功。**两组所有生成响应均未使用quantity表达式**，因此不能把多答对1题归因于单位换算机制，也不能将4条中的25个百分点当总体增益。增加工具提示也会扰动其他操作选择；后续需要匹配的演示/训练和模块消融，而非从这一点估计宣布有效。

一例因表格超过8K上下文在两组均失败，一例因answer未终止操作块在两组均失败。筛选只保证表内出现单位，不保证问题需要单位运算；这是协议的已知局限。后续增加预先定义、人工核验的单位必需诊断题，同时保留无筛选完整开发集上的比较。

原始输出、协议、代码hash及绑定官方分数位于本机runs/quantity-candidate/results和服务器runs/quantity-candidate-v1/results。首次运行冻结于code；SI大小写进一步收紧后存为独立code-v2，不覆盖首轮代码或重新选择样本。当前本地代码还补充B0能复用同一来源池而不强制启用操作提示的兼容性检查；后续实验需以新代码快照固定，不复用旧代码身份。

## 8. 原创性与贡献边界

使用并引用公开方法、遵守代码许可、注明改动是正常研究路线；“没有逐字抄袭”不等于具有论文创新。正式写作前对条件约束、程序溯源、类型执行、程序融合及自适应计算分别做专项查新，记录已有思想—本文新增—对照实验。当前两个名称属于候选贡献，不能在检索和实验前保证首创。

论文重点应是：条件与证据如何联合约束语义链、这种表示怎样支持可靠压缩蒸馏、哪些题型和成本区间获得收益。保留旧激进压缩的负结果、当前数据不足及失败边界，不用更换名称、只展示最好种子或选择性删除困难样本达成“全指标超过”。
