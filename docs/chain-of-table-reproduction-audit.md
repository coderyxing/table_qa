## 关键修正：不能把已有子串校验当作新增创新

operations/add_column.py中的add_column_act已经拒绝空值、重复列、全同值等情形，并遍历原表各列，要求整列派生值逐行来自同一原列的子串。它还会拒绝以number of开头的列名。因而“增列有来源”“复制原格文本”“子串校验”都不是本项目可以独立宣称的首创。

本项目extract增加确定性规则、字符位置记录、明确异常和来源链，属于接口能力补齐与可审计实现。是否具有研究价值，需要额外实验；论文核心新增仍应是**自然语言问题条件到程序的显式绑定及其跨步骤保护**，以及**在这种条件约束下的压缩分块蒸馏**。这些候选贡献也需继续查新，不能仅凭与这一篇论文不同便保证原创。

## 逐项差异与移植要求

|方面|固定原代码行为|本项目当前差异/正式对照要求|
|---|---|---|
|规划接口|根据当前表与历史选择下一个操作，再单独生成参数|A3/A4一次性完整计划不是原算法；正式基线必须分开这两次生成|
|操作集合|add_column/select_row/select_column/group_column/sort_column|当前DSL额外有数值筛选、算术、断言等；不能声称操作能力完全一致|
|操作顺序|possible_next_operation_dict限制有向顺序；每种保留的操作最多一次，支持skip与END|“有操作顺序约束”本身已有；本文需证明更具体的读写/问题条件约束收益|
|增列|先处理前3行，然后对后续行继续生成；最终整列子串检查|确定性抽取是受限子集，不能拿它替代完整增列并仍称忠实复现|
|行列选择|采样8条；候选按分数累计；act默认union_num=2|不能改成一次贪心、仅保留最高一个候选而不披露|
|候选分数|utils/llm.py用返回顺序构造fake_conf=(n-i)/n，再取log；并非模型token似然|移植时复现此约定或单列修改，不能冒称真实置信度|
|采样参数|chain.py默认行/列temperature=0.5、每条150 token；其余多为0/150|论文附录C列过1.0/200等不同设置；代码默认与论文参数两套分别保存，不能挑更弱者|
|分组|存储group_sub_table等辅助信息；最终查询可看到分组结果|不同于直接用group_aggregate覆盖全表，需要移植附加状态而非只改操作名|
|最终回答|最终表和问题调用simple_query，TabFact返回YES/NO；有演示|当前状态断言不是同一种输出接口；基线需保留其最终查询|
|任务入口|公开run_tabfact.py及final_query提示以事实验证为主|WikiTQ/FeTaQA需依据论文补任务提示，明确“任务扩展”而非声称三任务原脚本均已发布|
|数据清洗|load_data使用Dater raw2clean映射；找不到时回退原句|原句/清洗句应审计并分组；映射和测试ID尚未对齐|
|表格展示|helper.table2df/table2string默认最多100行；部分函数用前3行|不能静默截断后与完整表格比较；原始展示策略与统一全表策略分列，统计受影响样本|
|基础模型|旧OpenAI ChatCompletion后端|本地Qwen属于底座移植，不等同于PaLM2或GPT3.5原报告复现|
|生成停止|普通文本补全|现有LocalModel在完整JSON处停止，不能直接复用为原提示文本后端|
|运行异常|部分批量路径捕获异常后留下None；有响应缓存|正式比较保留失败，禁止缓存速度收益；解析/异常改动注明|
|代码执行|若干eval用于操作分派和结果解析|移植时用白名单分派和受限数据解析，保存逐项补丁，不执行模型任意代码|
|许可|主代码Apache-2.0，third_party提示MIT|若实际复用，随分发保留相应许可和归属；当前下载仅检查，核心extract为本项目独立实现|

## 正式基线尚需完成的工作

1. 在独立baseline包移植文本生成后端，支持temperature、n=8、原始输出及全部token/耗时统计；保留随机种子与返回顺序。不得使用JSON停止器。
2. 原操作/提示和执行状态逐项对照，保留候选合并、增列行循环、分组附加表、最终查询以及许可；进行确定性回放核对，不把工具能力差异误认为模块收益。
3. 对齐数据清洗和ID、任务提示、评价器。公开结果仅在此核验后直接比较；清洗和任务扩展不同就单列。
4. 分别运行代码默认配置、论文参数配置和统一预算配置。任何预算上限导致提前停止都计失败/预算耗尽，不能只给本文更多候选或上下文。
5. 先在允许的训练开发样本上检验接口；冻结后才进入验证选型和最终测试。

当前状态：**来源核验、TabFact原语句本地后端和小规模运行已完成；三任务完整对齐尚未完成**。新增三组extract诊断只比较本项目自己的接口，不包含Chain-of-Table，不用于声称超过它。

## 已完成的TabFact/Qwen迁移诊断

tableqa/chain_of_table.py沿用经验证的原操作模块、原提示、状态与最终查询；仅把模块eval替换为静态名称白名单/字面量解析，用本地文本生成后端代替旧OpenAI调用。保留原8候选、temperature=0.5、union_num=2及返回顺序代理分数，不使用完整JSON停止器、不读取参考答案。服务器通过原源码合成回放：11次候选生成、4次逻辑请求，包含8候选选列；这是接口测试，不是模型准确率。

随后固定取语义诊断集顺序中的前2条TabFact训练输入，同一32B模型运行代码默认操作配置、raw_statement、8K上限。结果：第1条精确输出YES且正确；第2条输出YES并附解释，按原评测器的精确标签规则判失败，整体1/2。这是2条训练诊断，不代表总体分数，也不支持与本文方法的优越性结论。

|输入|候选生成|逻辑请求|输入token|输出token|结果|
|---|---:|---:|---:|---:|---|
|2008芬兰锦标赛名次|20|6|46708|1470|YES，正确|
|高尔夫两轮均值|22|8|49399|1708|YES附解释，严格格式失败|

第二条回答的算术内容与题意相符，但不能在看到结果后改评测规则、只宽松解析基线或只宽松解析本文。未来若增加统一标签规范化，必须预先固定同一规则，对全部方法和全部输入重评，并与原版精确解析分表。当前原始输出和失败保留。

候选采用本地顺序采样，时间不代表优化批量后端或原API速度，latency_comparable=false。没有Dater清洗映射、未对齐原论文测试ID，也没有WikiTQ/FeTaQA任务扩展；因此仍明确标为“原源码TabFact/Qwen迁移诊断”，不能叫完整论文复现。
