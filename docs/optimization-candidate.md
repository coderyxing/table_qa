## 候选一：全签名约束的子序列压缩

输入为原始表格状态\(s_0\)和教师链\(\tau=(a_1,\ldots,a_L)\)。候选族\(\mathcal S(\tau)\)仅包含原链的有序子序列，且保留answer及所有显式requires_feedback操作。目标为：

\[
\tau^*=\arg\min_{\tau'\in\mathcal S(\tau)}
\bigl(|\tau'|,\;|\operatorname{JSON}(\tau')|_{\rm chars}\bigr),
\quad\text{s.t.}\quad
\operatorname{Sig}(E(s_0,\tau'))=\operatorname{Sig}(E(s_0,\tau)).
\]

这是按操作数量、再按JSON字符数的字典序目标。第二项是字符数，不冒充token数。Sig包括列、行值、来源、累计证据、答案和answered标志，不仅比较最终答案。

`optimization.optimize_operations`按保留操作数量从少到多枚举；每个候选经过依赖验证、白名单执行和全签名比较。默认最多4096个候选。只有最短可行层完全检查完，才报告optimal_in_deletion_family=true；达到上限则明确标记未证明最优并返回已验证候选。它不是融合操作、重写任意程序的全局优化器。

该函数不接收标准答案或评测分数。`verify_subsequence_rewrite`在构建训练记录前再次验证原操作顺序、反馈标记和全签名。旧legacy压缩也补上反馈标记保护，避免无作用投影把边界标记一起删除。

重要限制：这是**指定原表上的执行等价**，不是对任意反事实表格的逻辑等价，更不是自然语言题意正确性证明。数据上恰好无作用的条件可能被删除；因此仍需跨表格、鲁棒性、案例和人工过程审核，不能从签名相同直接写“完全保留推理语义”。

## 候选二：训练端状态成本分块

对压缩教师链重放，得到每个位置的状态\(s_i\)与已执行历史\(H_i\)。候选块\(B_{i:j}=a_{i+1:j}\)的成本为：

\[
c(i,j)=\alpha\,n_{\rm in}(s_i,H_i)
       +\beta\,n_{\rm out}(B_{i:j})+\kappa.
\]

输入token通过实际学生tokenizer、共同system prompt和`inference.context`计数；输出为完整操作JSON目标加EOS。默认\(\alpha=\beta=1,\kappa=128\)，单位是加权token代理，不是GPU秒数。这些系数尚未完成时延校准，不宣称默认最优。

可行边必须同时满足：操作数≤4、不跨显式反馈边界、answer单独监督、实际prompt+target≤4096、target≤学生输出上限512。答案单独监督与现有损失定义保持一致。

用有向无环图上的最短路径求解：

\[
D(0)=0,\qquad
D(j)=\min_{i:(i,j)\in\mathcal E}\{D(i)+c(i,j)\}.
\]

`optimization.state_cost_partition`保存可行边、每条边token、选择的边界和固定分块成本。它对既定教师链和成本函数的可行分区空间求最优，不证明在线任务质量或时延最优。公式对应的实际用途是生成更合适的**训练操作块目标**。

此处不增加所谓“创新损失”，仍使用原\(L=L_{block}+\lambda L_{answer}\)。学生从当前状态/历史预测块内容及JSON结束位置。测试预测不运行需要未来教师链的DP，不接收未来操作或标准答案；训练端标签选择与在线决策必须在论文中分清。

忽略状态变化的消融只把成本目标中的状态替换成初始状态，保留相同执行历史；可行性安全检查仍用真实状态。学生训练输入始终是真实当前状态，不能让该消融误变成另一种输入协议。

## 当前149条真实轨迹的离线结果

`scripts/audit_optimization.py`已完成压缩×分块对照，保持相同来源和原始教师链，逐条重放、检查训练长度并保留记录哈希：

|变体|训练记录数|原始目标token（平衡前）|相比旧固定分块发生变化的来源|
|---|---:|---:|---:|
|legacy压缩＋固定块|311|17976|0|
|搜索压缩＋固定块|299|14376|69|
|legacy压缩＋状态成本块|311|17974|10|
|legacy压缩＋忽略状态变化的成本块|311|17974|13|
|搜索压缩＋状态成本块|299|14376|69|
|搜索压缩＋忽略状态变化的成本块|299|14376|69|

搜索将原始549操作降到435，约减少20.77%；相比legacy的547操作减少约20.48%。全部149条通过签名检查，并在删除子序列候选族内取得已证明的最短操作数。它们没有因此被重新标记为“人工过程正确”。

搜索压缩后，状态成本与固定块仅1条来源的记录不同；状态成本与忽略状态变化的记录哈希完全相同。成本代理合计469658→469543，只下降约0.0245%。这说明当前短链不能充分区分状态分块机制，**不支持自适应机制带来明显收益的结论**。相同记录、相同配置的对照复用结果，不重复训练后把随机波动当模块贡献。

补充完整交互审计`runs/optimization-audit-state-probe`：在legacy压缩的较长链上，状态与忽略状态的分块目标有6/149条不同；将两条路径均按真实状态重新计价，代理成本494370→491911，约下降0.50%。搜索压缩后两者路径仍相同。它支持“压缩会减少状态分块的作用空间”这一离线现象，尚不能推出模型性能或在线时延的因果结论。新审计与旧五组记录哈希一致，并补充样本/预测绑定及输出上限检查。

本轮固定目标最长184 token，搜索目标最长152 token；所有审计可行边含EOS的目标最长187，均低于512。后续长度与块大小实验仍需单独检查，不推断其他数据也能满足。

完整报告在`runs/optimization-audit/report.json`，逐来源报告含搜索证明、全部分块边和哈希；本机副本在`runs/server-verification/2026-11-05-optimization`。原始目标token不等于平衡、预算和对齐后的实际监督token，后者仍以训练exposure报告为准。

## 已启动的后续实验

**新教师轨迹对照。** `runs/interactive-teacher`从联合训练池预先抽取新60条（每任务20条，seed2029），排除此前开发输入，不按长度、标签或正确性挑选。先用32B A4整链，再用相同32B和B5交互接口、每次最多2个操作。这里的B5是教师调用接口，未加载学生adapter，不是把32B结果当3B成绩。

两者同为双A40 BF16、4096输入限制、每次1024生成限制、总8操作、最多1次修复。交互会改变调用总数和总token，并未控制为相同计算预算，必须同时报告质量与成本。每组完成60条后进行官方判分、配对分析和轨迹审计；FeTaQA仍待真人审核，不自动批准。该试验判断交互式执行反馈是否有助于收集更可靠轨迹，不替代正式依赖/证据消融。

整链/局部块接口还改变了依赖检查可见范围和失败回滚范围，不能把差异仅归因于反馈。后续依赖、证据和修复消融必须在同一种调用接口内受控比较。

**压缩训练控制。** `runs/optimized-student-control`已排队，等待双卡教师结束后，用单卡3B训练“搜索压缩＋固定4操作块”。对照为已完成的coverage B5，只改压缩规则，保持实际149来源、rank32、seed42、3epoch和40条验证ID；仍不等token。它不检验状态DP。训练前后均检查真实来源ID哈希，随后用同一WikiTQ判分与TabFact指标比较。在线质量与效率未知，负向结果同样保留。

本轮没有因为搜索算法离线成本下降而直接运行全部正式实验。优先验收教师质量、压缩监督效果与真正能区分分块策略的数据；随后再扩展等token、多种子及三任务完整实验。

## 复现入口

```bash
python -m tableqa build-records TRAIN_SAMPLES TRAIN_PREDICTIONS RECORDS \
  --mode B5 --compression-policy search --partition-policy state_cost \
  --tokenizer models/Qwen2.5-3B-Instruct --max-block 4 --max-target-tokens 512
```

命令保留审核门槛，并输出filter与optimization记录；tokenizer只从本地读取。固定分块使用`--partition-policy fixed`，忽略状态变化使用`state_blind`。验证记录必须显式`--validation-records`且来自当前协议允许的源验证集，测试输入禁止生成教师分区监督。

截至本轮，本机和GPU12均通过118项测试，包括全签名/证据保护、搜索上限诚实报告、反馈边界、DP与穷举解一致、无参考答案泄漏、长度约束、原固定对照一致与CLI产物验证。测试证明实现性质，不替代上述模型实验。
