# 问题条件义务验证器：独立原型与适用边界

本原型位于tableqa/contracts.py，未接入默认推理，也未参与curriculum-student-v1训练或评测。其作用是为后续条件保护实验提供可计算的验证接口，不是当前模型提分结论。

## 输入与验证

每个已声明条件包含id、问题字符跨度、原文quote、绑定的操作对象和前置条件ID列表。只接受白名单操作；不接受reference/label等额外字段，也不接受常量answer.value作为条件。引用以Unicode码点/end-exclusive校验。绑定使用规范化操作JSON严格匹配，显式反馈另行保护。

执行时保留未履行义务集合U。操作满足一个绑定后，才在私有候选状态中更新义务；执行失败则操作状态和义务都不提交。若一个条件需要前置义务，必须先完成；投影或聚合不得破坏其他未履行条件需要的现有列。聚合覆盖同名旧列也视为原列被破坏。最终answer出现时U必须为空。

\[
U_{t+1}=U_t\setminus Match(o_t),\qquad
Pred(c)\subseteq Fulfilled_t\ (c\in Match(o_t)),
\]

\[
Lost(o_t,S_t)\cap Reads(c)=\varnothing\quad(c\in U_{t+1}).
\]

公式分别对应操作绑定/前置依赖检查和跨块列保护。run_contracted_block返回新的状态、不可变tracker和带义务记录的轨迹；输入对象不被修改。verify_condition_rewrite额外检查原链/改写链在当前表上的完整状态和来源签名，以及反馈操作是否保留。

## 可验证的用途

“After 2020, which team has the highest score?”可声明年份筛选F、最大值选择M以及F→M。分块执行F后，可在下一次调用中继续保护M的分数列；先M后F、提前删年份列或尚未完成条件就回答，都会被拒绝。

另一个合成诊断中，排序已经读取所有分数，当前表所有行恰好都大于5，删除“above 5”筛选仍可能保持当前输出和证据签名。声明的筛选义务能拒绝这种改写。将某一行改成0后，被删筛选的程序与原程序答案不同，说明当前表重放相同不等于一般语义等价。

这些是确定性的实现性质与机制反例，不是模型训练、真实基准结果或原创性证明。

## 尚未解决且必须披露的限制

1. **条件抽取不完备。** 检查器只看到已声明条件。模型漏掉最高分等条件时，已声明条件100%履行也不表示题意完整；报告字段始终保留question_condition_completeness=not_proven。
2. **绑定不等于语义理解。** 有真实问题跨度，但比较符、列或数值可能绑定错误；本原型不证明自然语言到操作的正确性。
3. **严格操作绑定可能误拒合法替代程序。** 当前规范化JSON仍要求相同操作字段，等价的不同算子/别名/分解方式可能无法匹配。适合先做已审核教师轨迹保护与离线改写诊断；不能未经误拒绝率实验就强制限制全部在线解法。
4. **未来参数不能由测试教师预先提供。** 当前tracker可跨块检查，但测试时条件和绑定必须来自公开问题、表格和已执行状态，不能读标准答案或未来教师链。后续需要单独实现/训练条件预测或符号绑定，对其额外调用和token计费。
5. **不是普遍等价证明。** 当前表状态、证据和条件义务保留，仍不能证明任意新表都等价；额外无关条件、未声明范围及复杂逻辑可能遗漏。
6. **还需消融与查新。** 原Chain-of-Table已有操作顺序限制和子串检查；本原型是否在具体问题条件、跨块义务和压缩保护上形成充分新增贡献，仍需文献核验和受控实证。
7. **尚未验证聚合的行域。** 列仍存在、条件操作均出现，也不保证“总数”“筛选后数量”等统计的输入行集合正确。例如先筛选再执行绑定为总计数的聚合，单靠严格操作匹配仍可能接受错误范围。后续需显式行域/作用域标注与保留中间事实，不能把当前的列保护扩写为已经证明完整集合语义。

后续实验应先审核条件和绑定，报告抽取完整性、绑定正确率、误拒绝率和运行成本，再比较启用/禁用义务保护的同模型效果。不得把这个未参与本轮训练的原型归因到本轮任何正向或负向成绩。
