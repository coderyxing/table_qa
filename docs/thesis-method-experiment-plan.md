# 基于思维链引导与高效表格问答方法研究

## 研究方案与代码设计

本研究首先探索如何引导大语言模型（教师模型）将给定表格及其自然语言问题转化为可执行、可检查的表格操作链，并使这条链能够推导出正确答案、保留支撑答案的原表证据。随后，利用教师生成并经检查的操作轨迹训练小语言模型（学生模型），让学生学习如何根据题意选择操作、确定参数，并根据中间表格状态决定后续步骤。面对新的表格和问题时，学生独立生成操作并调用执行器，根据返回结果继续推理，最终给出准确且可追溯的回答。

第三章研究教师操作链校验和学生推理能力迁移。第四章研究局部视图下的长表操作链代码化蒸馏。两章共享操作链、执行反馈与师生蒸馏的设计思想，各自从公开底座起步，独立采集轨迹、训练和评测。

开题报告和发明材料提供了操作序列、逐步执行和师生蒸馏的起点。论文保留其固定模板作为对照，并把主方法改为由问题条件决定部分操作先后关系。范围选为单张结构化文本表。WikiTableQuestions（WikiTQ）是主问答任务，TabFact 是陈述验证扩展，FeTaQA 是自由文本回答扩展。视觉布局和嵌套表头留在研究边界讨论中。该安排让论文的主要结论建立在已有执行器和可复核的任务上。

| 论文贡献 | 具体机制 | 实验回答的问题 | 产物 |
|---|---|---|---|
| 第三章 基于条件校验与操作链蒸馏的表格问答方法 | 将题意条件绑定到行域和执行见证，用经校验的操作链及操作块监督学生 | 教师能否减少条件遗漏和范围错误，学生能否学会在新题上独立生成并执行操作链 | 教师轨迹、证据记录、学生适配器及效率对照 |
| 第四章 基于长表视图感知与操作链代码化蒸馏的表格问答方法 | 将视图生成、原表探查、代码执行和结果读出组织为可蒸馏的操作链 | 学生仅观察有界视图时，能否生成覆盖真实候选范围的计划，并根据执行反馈修订 | 独立长表轨迹、学生适配器、全表范围和效率审计 |

两项是待验证的论文创新候选。第三章内部设置教师可靠性和学生迁移两组实验。第四章独立检验局部观察、原表执行与反馈蒸馏的效果。

## 第三章 基于条件校验与操作链蒸馏的表格问答方法

### 方法定义

现有执行器能检查列引用和操作是否合法。论文进一步区分“操作执行成功”“使用了正确的行域”“覆盖了已识别的题意”。例如，假设原表有 5 场比赛，其中 2021 年之后有 3 场。题目问“2021 年之后的比赛占全部比赛的比例是多少”，正确计算为 3/5。先筛选再做两次计数得到 3/3，两次计数都可正常执行。需要同时保存分子与分母所依赖的行域，才能定位这个错误。

对一个条件定义 \(c=(id, span, kind, args, scope, predecessors)\)。`span` 是原题的 Unicode 左闭右开字符区间；`kind` 在第一版只支持比较筛选、极值、计数及终点读出或断言；`args` 绑定原始列 ID、比较符和值；`scope` 表示原表全集、某个已验证过滤结果或某个明确分组。`predecessors` 是其他条件 ID。比值由受限算术读取已经验证的两个计数事实。每条条件同时记录提取状态和规则版本。

执行状态 \(X_t=(S_t,U_t,W_t)\) 包含当前表、待满足条件与已验证见证。见证由执行器生成，包含执行操作、输入行域标识、输出行域或计算值、参与运算的原始坐标以及依赖的见证 ID。第一版用排序后的原始行 ID 集合表示无序行域，用明确分组键和成员集合表示分组。极值另外校验方向、列、并列处理以及极值是在预期范围内求得。行位置只在题目明确依赖原始顺序时参与语义匹配。

每个块按以下规则运行。

1. 从公开问题和原表产生条件候选。先用明确的数值、比较词与列链接识别可覆盖条件。将含糊的作用域或列绑定标为 `unresolved`，保留原题。需要模型辅助抽取时，单独记一次调用并在对照中共享候选。
2. 先在私有状态执行操作，再依据执行前后状态生成见证。只有当条件的语义参数、实际输入行域和前置条件均匹配，才将其移出待满足集合。操作别名和可证明的等价形式可归到同一语义类型；无法归一的形式进入误拒检查。
3. 投影或聚合前检查待满足条件所需的列和行域是否仍可读。对分母例子，允许先在全表生成计数事实并保存，再执行筛选；也允许保留只读原表并显式在该行域计数。两个读法按实际输入域判定。
4. 已支持且已声明的条件全部满足、终点读出的来源可解析时，提交受校验的答案。对存在未解析条件或抽取器未识别到支持条件的题，使用预算内常规推理并标记 `unverified`。块失败时表、已完成条件、临时引用和见证一起回滚，再用失败原因发起有限修复。修复耗尽后保留失败及完整成本。

TabFact 的条件要区分选取对象和检验断言。比如“2021 年该队有 0 次擒杀”，先按年份和队名确定对象，再在该对象域检查值是否为 0。若对象存在但值为 2，断言为假；对象为空时根据预先声明的存在性、否定或量词规则处理，超出规则的题归入未验证。成功返回否定标签也应记录已经执行的断言见证。FeTaQA 可以把可核查事实交给答案生成器，最终文本的事实一致性另行评价。

### 教师操作链实验

| 配置 | 固定和变化的条件 | 用途 |
|---|---|---|
| A0 同底座直接回答 | 同数据、表格视图、模型和总体资源上限 | 端到端参照 |
| A1 固定模板 | 按开题与专利的方法描述独立实现模板；仅在模板适用题型做机制归因，同时记录全队列覆盖和回退 | 检验从固定顺序到条件依赖的价值 |
| A2 Chain-of-Table | 固定附件提交的原始 TabFact 入口；同模型移植版本单列；WikiTQ 移植仅在验证操作和判分后纳入 | 界定与外部动态操作链的差别 |
| A3 仅执行合法性 | 使用现有共同操作池、类型层、候选条件提示、证据表示及修复上限，关闭条件校验 | 主要内部对照 |
| A4 条件匹配 | 与 A3 相同，增加条件与前置关系检查，行域检查处于观察模式 | 衡量条件匹配增量 |
| A5 完整方法 | 在 A4 上增加行域、依赖证据和提交前终点检查 | 主配置 |
| A5-无修复 | 完整方法，失败后直接结束 | 衡量修复引入的质量和开销 |

A3–A5 每题共享同一候选条件及相同状态字段格式，已履行条件由各自实际执行计算。三组计入同样的抽取开销。主对照使用相同教师、操作池、每块上限、总操作数和总调用预算。另做配对的类型视图开关，作为输入工程分析。人工标注条件只用于离线评分，人工条件输入实验单列为诊断上界。

- **质量主指标**。WikiTQ 用官方指称准确率；TabFact 用标签准确率，并按真假标签给出结果；FeTaQA 报告同一实现下的语料 BLEU、ROUGE-1/2/L。有双人复核时再报告陈述级事实支持率和分歧，按样本保存审核记录。
- **机制主指标**。在冻结的双人标注子集分别报告条件抽取召回、列和行域绑定准确率、已执行题意覆盖率、正确答案但过程错误比例，以及有效替代程序误拒率。对自动接受的结果报告覆盖率及其准确率。全队列分母包含未覆盖题、解析失败、超限和修复失败。
- **机制诊断**。准备最小测试对，包括全表总数与过滤计数、极值先于筛选、并列、空集断言、数值单位歧义和重复表头。对少量独立标注题构造改变一个单元格的配对表，独立核验改动后的答案和行域，检查原表恰好正确的程序在改表后是否仍成立。该诊断属于已有反事实评估思路。
- **过程产物**。导出教师链及每一步条件见证。训练用途须满足数据划分检查、可重放及官方答案弱筛选。记录各条件的确认层级 `weak_answer_match`、`contract_checked` 或 `human_reviewed`。同时保存拒绝轨迹、拒绝原因和被接受来源的题型分布。

实验一的关键对照为 A5 对 A3，A5 对 A4 定位行域增量。可用现有 60 题开发队列接线与估计难度；既有的 8 条 B2/B5 退化案例用于回归复现。开发验证前按题型冻结审核样本，从开发配对的正确性分歧率估算正式队列达到目标效应所需规模。正式主结论依赖另外冻结的评测队列。若正确答案增加主要来自额外修复或抽取成本，按对应对照和预算结果限定结论。

### 保留条件和反馈边界的操作块蒸馏

学生蒸馏复用本章的见证接口。同一原表上两个程序得出相同答案，可能仅仅因为当前所有行都恰好满足一个条件。编译时保留已验证的条件及其实际行域，避免蒸馏把这类条件当作冗余步骤删除。第二个问题是何时需要再次调用模型。有些中间值可在同一块内用引用传递，有些结果需要模型重新看见才能决定下一步。两类依赖分别处理。

1. **压缩候选。** 对教师链执行有界子序列搜索。保留终点、必要条件见证和反馈检查点，候选必须在原表重放通过，且终点输出和证据、每项已验证条件的实际行域及语义值与原链一致。初版继续保留现有全状态签名约束，拒绝后回退到原链并记录原因。反事实只用于离线诊断。原表签名和见证相同可用于审计本次改写。
2. **区别数据依赖和模型观察。** 若后续算子的参数可以用已绑定常量、原始列 ID 或前步类型化输出引用表示，则允许按序在一次调用内生成。比如对过滤行域求最大值后读取命中行的城市，执行器可以解引用该行域和候选行。若下一操作的类型或参数需要模型根据新出现的候选值、含糊并列或解析状态做选择，则在该结果后提交块并重新构造提示。正常数据依赖允许块内顺序执行；需要模型选择的未绑定参数必须等可见状态。
3. **编译训练目标。** 对训练链依据可检查的数据来源规则生成边界，无法判断时采用保守边界。边界标签应记录原因，并在真实多步轨迹中人工抽查。以单步或固定块为参照；可选地用现有最短路径从合规分区中选低成本路径，边代价为实测 tokenizer 输入 token、输出 token 和调用开销代理的加权和。最短路径只在满足长度、反馈与类型约束的离线分区中选目标。
4. **训练与在线执行。** 用 Qwen2.5-3B-Instruct 等已有学生底座在同一 LoRA 训练器上学习 `operations` JSON 块和终止位置。操作与答案用现有监督交叉熵，固定或显式消融答案权重；这是序列级蒸馏。线上输入只包含问题、当前状态、可读引用与待满足条件；学生在此基础上生成下一块。执行器逐步验证新块、原子提交结果，遇到必须观察的决策则结束当前块。模型猜测尚未观察的离散选择时拒绝该块并按共同预算重试。

反馈边界的判定应与在线可观察状态一致。第一版将需要重新选择的动作写成明确的 `observe` 请求，依据已知操作类型和引用来源检查。块开始时可直接引用已提交结果；块内新结果只允许用于声明为确定性的引用槽位。生成块时尚未出现的候选，若需由模型挑选，必须通过 `observe` 进入下一轮。执行器可检查声明的引用和观察请求；模型可能把未观察的选择伪装成直接常量，需结合列和值的绑定约束限制，并在审核子集测漏检率。固定块组与约束块组使用同一动作协议、同一在线检查器和相同最大块长。固定块目标先按统一硬约束切分，约束块目标进一步根据可绑定依赖和状态成本选择边界。若两组标签或上线策略实际上相同，记录为当前数据无辨识度。

### 学生蒸馏实验

主矩阵先使用同一个冻结的 A5 教师来源池、同一个初始学生、相同表格表示和条件提示。所有学生操作组使用共同执行器。答案组按任务直接输出答案。

| 配置 | 训练信号与粒度 | 主比较 |
|---|---|---|
| D0 | 同来源官方答案监督 | 小模型常规监督基线 |
| D1 | 同来源完整教师操作链，逐步预测和执行 | D1 对 D0 检验操作监督能否改善新题上的学生问答；同时检查 D1 的链执行成功率、条件覆盖和证据支持 |
| D2 | 保留条件见证的压缩链，逐步预测和执行 | D2 对 D1 检验压缩 |
| D3 | 与 D2 同链，固定上限分块，遵守共同硬边界 | D3 对 D2 检验合并调用 |
| D4 | 与 D2/D3 同链，使用条件和反馈信息选择分块 | D4 对 D3 检验自适应边界；D4 对 D1 检验整体取舍 |

附加两组小规模受控比较。其一在 D2 中把条件见证保护改成只比原表状态与证据签名，分别在改表诊断及正式队列看关键步骤是否被删。其二使用 A3 与 A5 都能生成可重放且答案匹配轨迹的训练来源交集，保持 D4 其余设置，比较教师轨迹来源。同步报告各自全量接受率，防止交集结果掩盖可用数据覆盖的差异。

- **公平训练。** 至少报告一组同来源、同轮次结果和一组同来源、接近目标 token 的预算对照。预算版用完整记录匹配，分开报告操作与答案监督 token、每任务来源曝光、重复率、实际优化步数和有效 batch。若预算裁剪导致来源集合变动，报告交集结果和变动数量。使用现有梯度累积修复版训练器，主对照和最终配置使用至少 3 个随机种子。
- **效率测量。** 主比较是 D4 对同一硬件上的 D1、D3。固定单张 A40、精度、batch=1、上下文和模型版本，预热后交错顺序重复计时，计入抽取、模型、执行器和修复，禁用响应缓存。报告 P50/P95 端到端延迟、累计输入与输出 token、调用次数、失败和回退成本、峰值显存。32B 教师作为准确率和系统成本参照，表中明确双卡配置。另报离线采集、审核与训练开销。
- **成功判据。** 正式评测前在开发协议登记主质量指标、允许下降的上限及预期的最小有效提速。例如先以 2 个百分点的准确率差和 15% 的 P50 改善作为待论证工程目标，结合开发方差和业务需求冻结。正式报告按表配对 bootstrap 的差值区间，质量下界达到预设容忍范围并达到效率门槛时，才主张在该精度范围内提速。若 D4 与 D3 的块标记几乎相同，或 D4 降低调用却提高 P95，分别报告结果，论文按实测限制主张。
- **分层与泛化。** 全队列结果为主。单独报告无需反馈、需要反馈及教师链长度等机制分层；按教师预测定义的分层明确标为事后诊断。若开展域外实验，优先在 WikiTQ 做按表且按主题留一，冻结主题规则和样本来源；跨任务迁移作为扩展，目标任务验证数据不得参与零样本选型。

本地 192 条新弱筛选轨迹的已有审计中，状态分块相比固定分块只降低约 0.23% 的 token 代理成本，且原始显式反馈标记为 0。先对真实轨迹回标反馈需求，统计实际可合并的步骤、出现有意义边界变化的比例、固定块重放失败与等价性误拒。若开发审计显示反馈边界极少，停止扩大 D4 训练，保留 D0–D3 验证学生迁移、条件保护压缩和块执行的质量与效率取舍。

| `tableqa/evaluation.py`、`mechanisms.py`、`reporting.py` 与 `scripts/` | 已有报告、机制分析、原版基线脚本和官方判分入口 | 增加行域、终点断言、误拒、反馈边界及计时审计；按样本 ID 配对，固定官方判分版本 |

拟定接口如下，名称可随现有模块收敛。

```python
extract_contract(question, table) -> Contract
run_checked_block(state, obligations, operations, policy) -> BlockResult
compile_teacher_trace(sample, trace, tokenizer, policy) -> CompiledTrace
make_student_records(sample, compiled, mode) -> list[TrainingRecord]
```

`run_checked_block` 内部先复制执行快照，在每次操作后生成见证和校验行域，仅在整个块通过后返回可提交的新状态。训练记录只包含该时刻在线可获得的公开输入，未来操作仅出现在监督目标中。`compile_teacher_trace` 拒绝测试划分；缓存按代码、输入、模型及协议哈希区分。预测与标签分别存放，判分后再用数据集、划分与样本 ID 关联。

建议产物为 `protocol.json`、`teacher_traces.jsonl`、`compile_audit.jsonl`、`train_exposure.json` 和 `predictions.jsonl`，以及配对报告。轨迹最少保存 `dataset/sample_id/split/table_hash`、`contract_version`、操作、状态签名、见证、证据坐标、错误及开销。训练的条件版本必须与推理时匹配。用新实验目录隔离运行，保留全部结果和失败。

#### 执行与编译示例

以下是占比例问题的拟定操作协议。作用域标识与执行事实为执行器内部对象，模型只输出白名单动作和受限引用。执行器统一处理空分母并按任务协议渲染分数或小数。

```text
block 1
  count(scope=original) -> total
  filter(scope=original, column=c_year, cmp=gt, value=2021) -> recent
  count(scope=ref(recent)) -> matched
block 2
  answer(ratio(numerator=ref(matched), denominator=ref(total)))
```

固定逐步模式用四次预测生成上述四个动作。块模式将三个操作合成一个监督目标，最终读出作为单独目标，目标调用数为二。若候选轨迹将 `total` 的输入改成 `ref(recent)`，即便两次数值在某张表上相同，行域检查也拒绝该绑定。若读出涉及需要模型判断的并列候选，则提交候选并在下一调用提供其实际值与出处。示例说明协议行为，实际调用需包含条件抽取与失败重试。

编译器先重放原链，记录每个操作前的快照和提示 token；再按确定性顺序尝试删步，验证候选的终点签名和见证。对通过的操作序列枚举从位置 \(i\) 到 \(j\) 的块，按同一在线检查器预演动作。块跨越硬边界、引用不可解析、超过最大块长或超过上下文预算时不生成边。D3 在每段内优先取满足限制的最长块；D4 复用最短路径，计算 \(D(j)=\min_i[D(i)+\alpha n_{in}(i)+\beta n_{out}(i,j)+\kappa]\)，并保存完整边表。编译失败时 D2–D4 使用未压缩的合法链重试；各主组采用同一可构建来源集合，并公布失败和回退的比例。训练端允许使用已采集的完整教师链，线上按当前块的公开快照执行。

首轮接线使用已有 Qwen2.5-32B 教师与 3B 学生。开发起点可用单请求 8K 上下文、512 生成 token、最多 8 个操作、1 次修复、块长上限 4。实际总调用上限需包含解析与修复，在 A3–A5 和各学生操作组内分别统一；短答与长答如需不同上限，按任务提前固定。训练从已验证的 rank 32、有效 batch 16、学习率 \(10^{-4}\) 起步。首轮使用一个种子核对训练数据与端到端执行，随后只对冻结主配置与其主要对照扩至多个种子。参数是开发起点，正式值写入协议及代码快照。

首轮实验服务器选定 GPU14。把项目运行目录、模型权重、下载缓存、数据和检查点放在 `/memory` 下有写权限的项目子目录。部署后从该目录运行 `bash scripts/preflight.sh`，核对两卡型号和空闲显存、互联、PyTorch 的 CUDA/BF16 支持及工作盘容量。32B 教师使用双卡分片，以 `batch=1` 试跑并记录峰值显存和单题耗时，再执行 60 道开发题的 A3/A4/A5 对照。教师轨迹采集结束后释放双卡，3B 学生使用单张 A40 训练；正式延迟对照固定同一张卡和同一推理配置。

| 顺序 | 工作 | 进入下一步的验收 |
|---|---|---|
| 1 | 固定分割、参考源码和配置；在历史案例与最小表实现行域执行见证 | 覆盖遗漏条件、合法替代、并列、空集合及块失败回滚；操作输入中查不到参考答案 |
| 2 | 跑 A3/A4/A5 开发配对；双人复核一批条件及行域，估计误拒与覆盖 | 具备条件遗漏、行域错误、额外调用和修复的逐例归因；以独立验证集冻结方法 |
| 3 | 仅在训练划分采集 A5 轨迹并编译 D1–D4；优先审计现有 172 与 192 条训练轨迹是否满足新协议 | 记录共同来源交集、见证保留率、监督预算和实际边界差异；对照产物有可辨识差异才扩大训练 |
| 4 | 用修复版训练器开展学生开发试验，选定质量容忍范围和速度门槛 | 校验 LoRA 已加载、训练曝光与计划一致、学生线上无需未来教师链 |

训练、开发、测试按官方划分起步，对跨划分重表优先从训练和开发来源排除，正式集保留官方分母并登记交叉覆盖。题型分层可用题面和表格特征；正式统计同时报告预注册全体和子组结果。已有开发表或确认表用于调试时标明已接触。FeTaQA 没有独立人工审核时，允许作为普通答案监督及自动评估扩展，主要操作蒸馏结论落在 WikiTQ 与 TabFact。

## 第四章 基于长表视图感知与操作链代码化蒸馏的表格问答方法

### 数据与可见预算

使用 DataBench 的 SemEval 完整表任务及发布的训练、开发和测试划分。以表 ID 和指纹检查跨划分重复，按同一学生 tokenizer 计算完整表提示长度，报告全量和超出上下文的长表子组。单轮上下文为 4096 token，预留 512 token 生成空间。局部视图最多 8 列、16 行、2048 token，先达到任一上限即停止扩展。视图标记 `coverage: sample`，用于展示字段、类型和取值示例。实际统计范围由题意与执行计划确定。 [数据与划分](https://huggingface.co/datasets/cardiffnlp/databench) · [官方评测任务](https://aclanthology.org/2025.semeval-1.324/)

### 操作原子与候选范围

| 原子 | 参数与执行结果 |
|---|---|
| `build_view` | 学生根据问题、列名与类型生成列选择和取样策略。执行器返回带稳定行列 ID 的有界样例。 |
| `probe_unique_values` | 按列 ID 和已核验的可选条件扫描原表，保存完整去重集合和结果 ID。集合能放入剩余提示预算时返回全量，否则反馈数量、有限样例和 `complete_in_prompt: false`，后续原子可引用完整结果。 |
| `execute_code` | 接收白名单 JSON 计划。执行器核验列、类型、筛选依据和分支范围，在只读原表上完成条件查找、分组、计数、求和、均值、极值或两项统计的比例。 |
| `read_result` | 引用本次查询的已执行结果及输出字段，读出答案、原表指纹、分支范围和证据。长列表由执行器从结果引用读出。 |

开放式比较和枚举由 `group_by`、`distinct` 等操作在题意指定的原表范围内产生候选。题目明确限定候选或排除某个值时，筛选必须绑定原题中对应的条件，探查可用于确认实际表内写法。仅依据样例构造的枚举条件返回 `UNSUPPORTED_ENUM_FILTER`，同样检查把 `in` 改写成多个等值条件或拆成只统计样例类别的分支。首版只强制核验明确支持的条件，含糊范围标为未验证并记录。

例如，“哪个品牌总销量最高”需要在原表按品牌求和后取最高组。视图只出现苹果和华为时，原表中的小米仍参加比较。“苹果和华为中哪个品牌总销量最高”可使用绑定到原题的显式限制。“除北京外还有哪些城市”可以直接在原表去重并排除北京；只有后续模型决策确实依赖额外类别信息时才调用探查。评价时分别检查候选范围、聚合语义和最终答案。

### 教师采集与学生蒸馏

1. 32B 教师只在第四章训练表上通过只读工具生成视图策略、可选探查、代码计划和读出。入池前重放并检查计算范围、证据和答案，区分弱筛选与人工复核。
2. 按线上学生可见状态重建每条监督记录。教师独自探查获得的类别必须经过学生可执行的探查公开后才可作为后续目标依据。保留轨迹与排除原因。用公开 3B 底座和现有 LoRA 训练器学习每个原子的参数。
3. 用初版学生在训练表上生成计划，采集类型、引用和范围错误，也收集可运行但将样例当全集的计划。教师依据同一可见状态和结构化反馈生成修订。修订通过重放及范围与答案核验后入池。线上最多三次常规步骤、一次探查后的续推理、一次修订，共五次模型调用。合法零命中与执行失败分别记录。

### 独立实验与验收

| 组别 | 条件与比较 |
|---|---|
| L0 | 固定视图，学生仅接受答案监督。 |
| L1 | 固定视图，公开 3B 底座生成计划并在原表执行。 |
| L2 | 固定视图，蒸馏代码原子与读出。对 L1 检验链式监督的增量。 |
| L3 | 学习视图策略、代码原子和读出。对 L2 检验视图学习能否减少字段和范围错误。 |
| L4 | 增加按需探查与真实错误修复监督。分开关闭探查、替换通用反馈、移除修复训练，保持对应重试机会。 |

统一初始学生、执行器、输入上限和调用上限。报告同来源及近似监督 token 的对照。额外比较 Top-K 子表执行与原表执行，并对相同候选计划离线记录范围规则开启和关闭的结果，区分模型主动生成正确计划与执行器拦截错误。

配对诊断有三类。第一类固定题目与原表、只换视图中的样例，测首次计划无依据枚举率和答案稳定率。第二类固定题目与视图、修改视图外的记录使正确答案变化，分别测固定计划重放和学生独立推理的成对正确率。第三类改变题目的范围要求，测试开放范围、明确候选、排除条件、高基数探查和合法零命中。正式队列报告官方准确率、范围拦截和误拒、探查与修复率、累计 token、CPU 执行耗时、P50/P95 延迟及峰值显存。首次计划和配对结果共同支持时，再主张学生学到了更能泛化的代码生成方式。

## 修订版实验入口与复现顺序

以下入口统一使用 `python -m tableqa.thesis`。训练、监督 token 预算和 WikiTQ 官方判分沿用仓库现有入口。预测配置为模型参数 JSON，例如 `{"model":"/memory/tableqa/models/Qwen2.5-3B-Instruct","adapter":"runs/chapter4/L2/adapter","seed":42}`。第四章正式分组统一使用同一个本地 3B tokenizer。先用一个种子试跑，冻结设置后用三个种子复现核心比较。正式延迟测量在同一张 A40 上预热后执行，保留硬件和运行顺序记录。

### 第三章三组实验

1. **3.1 教师操作链质量与误拒。** 用 `declare3 DATA MODEL_CONFIG DECLARATIONS` 生成题面绑定的条件与行域，保留未解析状态。用 `predict3 GROUP DATA MODEL_CONFIG OUT --declarations DECLARATIONS` 跑 `fixed`、`dynamic`、`conditions`、`row_domains` 和 `no_repair`。同一题的各组共享教师和输入数据。人工审核记录用 `dataset`、`id`、`candidate_hash` 关联首个进入语义校验的计划，并填入布尔字段 `legal`、`condition_omitted`、`row_domain_error`、`evidence_supported`。将各组输出合并后运行 `audit3 validation DATA ALL_PREDICTIONS REVIEWS REPORT`。以审核确认合法的计划为分母。开发误拒率严格大于 5% 时，使用 `predict3 llm_review ... --gate REPORT --reviewer REVIEWER_CONFIG` 比较复核前后误拒、错误放行和新增调用、token 与耗时。评测前冻结复核模型与配置。WikiTQ 官方准确率由 `scripts/evaluate_wtq_official.py` 分组计算，审计 JSON 的诊断分数单独保留。
2. **3.2 学生操作链蒸馏。** 只从训练集采集轨迹。同一批已重放的教师轨迹分别用 `python -m tableqa build-records` 构造 `B0` 仅答案、`B2` 完整逐步和 `B3 --compression-policy guarded_search` 条件保留压缩记录。取可编译来源交集作为同来源对照。再用 `tableqa budget` 做近似监督 token 对照并核对实际曝光，使用 `tableqa train` 和 `tableqa predict` 训练及测量。用 `student3 GROUP BUDGET DATA PREDICTIONS REVIEWS REPORT --input-limit N` 汇总。过程审核用 `dataset`、`id` 和已提交操作序列的 `candidate_hash` 关联，分别填 `operation_correct`、`parameters_correct`、`conditions_retained`、`error_propagated`。不可判断项填 null。
3. **3.3 分块与上下文管理。** 使用同一条压缩链，以 B3 逐步为参照，两个 B5 对照分别使用 `--partition-policy fixed` 和 `--partition-policy state_cost --tokenizer STUDENT`，并统一采用 `guarded_search`。用 `partition3 FIXED_RECORDS CONSTRAINED_RECORDS REPORT` 检查块标签差异，正式扩大训练前检查发生差异的原因。用 `student3` 比较同输入上限下的调用数、延迟、输入超限率和输出到达生成上限仍不完整的比例。可在过程审核中补 `reference_chain_length` 做链长分层。旧预实验的 0.23% 是代理成本差异，真实截断与错误传播结论由各自实测指标支持。

### 第四章三组实验

1. **4.1 长表问答主实验。** 安装 `pip install -e '.[train,databench]'`。将公开完整表保存为 `TABLES/<表 ID>/all.parquet`，运行 `prepare4 TABLES OUT_DIR --revision DATASET_COMMIT` 得到官方 train、dev（文件名 validation）和 test 清单。先在训练集用 `predict4 GROUP TRAIN TABLES TOKENIZER OUT --config TEACHER --teacher --limit 60` 审计试跑。正式采集去掉 `--limit`。用 `records4 GROUP TRAIN TABLES TOKENIZER OUT --traces TEACHER_TRACES` 重放并生成监督，L0 直接使用训练答案，L1 使用原始 3B。对 L2–L4 训练各自的适配器。用 `predict4` 预测，再运行 `main4 TEST REPORT --L0 P0 --L1 P1 --L2 P2 --L3 P3 --L4 P4`。报告给出全量、短表和长表准确率与样本数，以完整输入大于 3584 token 划入长表。以 L2 为共同参照，对 L3 和 L4 各自按原表重采样，估计长表增益减短表增益及 95% 区间。
2. **4.2 探查、反馈与修复消融。** 用初版 L4 学生对训练集执行 `predict4`，再用 `repair4 L4 TRAIN TABLES TOKENIZER REPAIRED --config TEACHER --failures STUDENT_OUTPUT` 在同一可见状态生成修订，重放检查通过后合并训练来源。消融组通过 `predict4 --ablation no_probe`、`generic_feedback`、`no_repair_training` 分开运行。最后一组须先用 `records4 --ablation no_repair_training` 编译记录并训练独立适配器，保留线上修订机会。每组执行 `cost4 TEST PREDICTIONS REPORT`，对照 CPU 导入、探查扫描、查询执行、模型调用和端到端耗时。CPU 扫描计时针对已经加载到每题独立 SQLite 内存库的原表，Parquet 读取和库内导入分别解释。
3. **4.3 候选范围配对诊断。** 人工在 dev 构造和审核 `view_swap`、`hidden_answer`、`scope_swap` 三类配对。每条包含 `source_id`、`kind`、`rules_hash`、`a`、`b` 与 `review`。两侧记录含题目、原表、稳定坐标视图、参考答案和答案类型。人工确认两个答案及合法范围后设 `review.answers_and_scope_verified`，用 `tableqa.data.digest` 对 `{kind,source_id,a,b}` 生成 `review.pair_hash`。运行 `diagnose4 GROUP DEV TABLES TOKENIZER DEV_REPORT --config STUDENT --phase dev --train TRAIN --pairs PAIRS --rules RULES_JSON`。正式运行把输入换为 test 清单和 test 配对，使用 `--phase test --dev DEV --rules DEV_REPORT`，由入口校验训练和开发的表 ID、指纹与重复题。首次计划人工复核填 `review.scope_legal[变体ID][计划哈希]`，再用 `--predictions` 读取原预测重算指标。报告按配对类型列出答案稳定性、成对正确率、首次无依据枚举与拦截、误拒，保存规则开关的逐计划重放结果。

### 磁盘与目录

下表按截图中 `df -h` 的显示值记录，实际可用容量会随其他任务写入而变化。

| 设备 | 挂载点 | 容量 | 已用 | 可用 | 使用率 | 用途 |
|---|---|---:|---:|---:|---:|---|
| `/dev/sda2` | `/` | 439G | 362G | 55G | 87% | 系统与日常环境 |
| `/dev/sdb` | `/memory` | 17T | 995G | 15T | 7% | 模型、数据、缓存、轨迹和检查点 |

`/memory` 是数据盘挂载点。宿主机 RAM 可用量通过 `free -h` 单独核对。表中 15T 是截图时文件系统的可用容量，个人目录权限与配额以服务器实际设置为准。

建议在 `/memory` 下使用已授权的项目目录，例如 `/memory/tableqa`。在该目录下配置 `models/` 存权重，`data/chapter3/` 与 `data/chapter4/` 分存数据，`runs/chapter3/` 与 `runs/chapter4/` 分存轨迹、检查点和评测。把 `HF_HOME` 指向项目内的 `cache/huggingface/`，把 `TMPDIR` 指向项目内的 `tmp/`，减少根分区写入。模型权重可共用，两章的适配器与运行目录分别保存。

```bash
df -h .
test -w .

```
