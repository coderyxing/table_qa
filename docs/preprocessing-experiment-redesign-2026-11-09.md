## Chain-of-Table 的输入路径

本次检查使用用户提供的 `chain-of-table..zip`。其中 Python 源码与已核验的 `1fd716c608f56e7d9d156ead432219c7ab9008af` 一致。压缩包 SHA256 为 `fc5579021d91a4cdf530af2bbd7190d019d79ae782b49f75c96052ba23e4d22a`。

| 位置 | 源码行为 | 实验含义 |
|---|---|---|
| `utils/load_data.py` | 按原陈述查 Dater 映射，将结果存入 `cleaned_statement`。映射缺失时填回原陈述，同时保留 `statement`。 | 分别记录精确命中、文本变化和回退。归因时按样本配对。 |
| `operations/add_column.py` | 只在首次增列提示中读取 `cleaned_statement`，将连续数字替换为 `_`，先展示前三行以确定字段和前三个值，再逐行处理剩余行。 | 数字遮蔽属于字段发现的局部视图。涉及比较阈值、计数、年份和否定的执行仍需使用完整题意。 |

| `utils/helper.py` | 将表线性化成表头及带行编号的文本。默认展示最多 100 行。 | 展示上限单独记录。原版设置和统一资源预算的设置分表。 |
| `operations/add_column.py`、`operations/sort_by.py` | 增列执行时检查结果是否逐行来自同一列的子串。数值排序有提取数字和首个小数点的规则。 | 保留来源检查思路。项目的数值比较采用整格解析和维度校验，避免把比分或赛季范围拼成数字。 |

压缩包内的 `raw2clean.jsonl` 有 1,971 行、1,966 个原句键。1,953 行清洗文本发生变化。5 条重复键记录的映射值一致。按增列代码的遮蔽规则，1,561 行清洗文本还会发生数字遮蔽。这些统计的分母是映射文件。映射对本项目训练、验证和正式评测队列的覆盖率在各队列 ID 对齐后分别计算。本次读取了映射文件和打包数据的目录，打包测试题的正文和标签留待正式协议冻结后处理。

当前本地 Chain-of-Table 移植把两个陈述字段都设成输入 `question`。补齐映射时给移植入口增加显式映射参数，保持现有算子顺序、候选采样、最终标签解析和回退行为。用一条回放检查映射文本只进入增列提示，另一条检查未命中时的提示。原始包数据、官方归一化数据及本项目 `joint_*_clean` 各自保留样本标识与来源。Dater 在其论文中还包括证据与问题分解，表归一化已有 NormTab 等工作。本项目把清洗与类型解析列入共享实验条件，将研究贡献集中在跨块条件保护和受该条件约束的分块蒸馏。 [Chain-of-Table 源码](https://github.com/google-research/chain-of-table/tree/1fd716c608f56e7d9d156ead432219c7ab9008af) · [Chain-of-Table 论文](https://arxiv.org/abs/2401.04398) · [Dater 论文](https://arxiv.org/abs/2301.13808) · [NormTab 论文](https://aclanthology.org/2024.findings-emnlp.203/)

## 数据输入的三个层次

1. 原始层保留数据集、划分、问题、表头、行列顺序及 `rN:cN` 坐标。原始表指纹用于跨划分排重，训练和开发继续采用已有的干净来源池。正式评测以冻结的官方题目队列为分母。答案和高亮字段仅供离线评价。
2. 类型层为原单元格附加 `{cell_id, raw, type, canonical_value, unit, status, rule_version}`。整格解析使用现有 `number` 和 `parse_quantity` 规则，扩展明确的频率单位前先做正反例回放。对于 `Ret`、`2014/15`、混合接口规格与歧义日期，保留文本并记录无法用于数值比较的原因。只有题目条件明确了比较范围，操作链才筛除相应行。返回原始表值时沿坐标取回原字符串。
3. 题意层保留完整题目和可选字段识别视图。条件记录绑定原题跨度、列、比较符、值或单位、行域及前置条件。`最少人口` 对应人口值的极值选择，`0 次擒杀` 对应目标行上的数值断言，`编号为 5` 保持为待履行条件直到实际筛选。对复杂作用域留出 `unresolved` 状态，单独记录。参考答案只用于离线诊断或训练数据评价。

类型注释可写为 \(M_{ij}=N(x_{ij},h_j)=(r_i,c_j,x_{ij},\tau_{ij},v_{ij},u_{ij},z_{ij})\)。\(x\) 是原值，\(\tau\) 是类型，\(v,u\) 是规范值与单位，\(z\) 记录解析状态。只有类型兼容、单位维度一致且解析成功时才执行数值比较。用 `tableqa/quantities.py` 实现值与单位规则，`tableqa/semantic_columns.py` 记录文本抽取跨度，新增的预处理记录保留原坐标与规则版本。

本次本地探针已确认当前执行器能读 `3,450` 和 `12%`，会拒绝 `2.67 ghz`、`Ret`、`2014/15` 和 `1 × 4.8 gt / s qpi i / o` 的数值化。频率单元格适合补充白名单，退赛标记适合验证范围约束，赛季和混合接口字段保留原文。用 `3200 MHz` 与 `3.33 GHz` 的比较验证单位换算，用 `Ret` 混入名次列验证适用行域，用 `2014/15` 验证季节表达保真。

## 实验一  类型化输入与跨块条件保护

研究问题分为两项。类型层能否减少错误数值比较和列值绑定错误。跨块约束能否减少条件遗漏、错误行域和过早回答。

| 组别 | 类型化视图 | 跨块条件保护 |
|---|---|---|
| R0 | 原始表 | 执行器常规合法性检查 |
| R1 | 原表加类型化视图 | 同 R0 |
| R2 | 原始表 | 启用 |
| R3 | 原表加类型化视图 | 启用 |

四组使用同一 32B 教师、原始样本、算子集合、解码上限、修复预算和证据显示策略。类型化视图通过明确的数值列或类型注释参与操作，保留源坐标。各类型视图内，开关组共享由公开问题和表生成的同一份候选条件，均计入提取调用成本。R1−R0 检验预处理，R3−R1 检验类型化条件下的约束，\((R3-R1)-(R2-R0)\) 观察交互。已测的坐标与可读证据结果单独保留，四组采用同一种证据表示来控制干扰。

从 \(U_0\) 初始化待履行条件。一次操作通过执行校验后，按 \(U_{t+1}=U_t\setminus\operatorname{Match}(a_t,S_t)\) 更新条件。`tableqa/contracts.py` 的现有原型能检查原题跨度、显式操作绑定及跨块列依赖。接入实验前需补行域检查和在线条件生成，检查器只对声明并正确绑定的条件负责。另测条件提取遗漏率和等价操作被拒率。现有约束原型的精确操作绑定可作为保守控制组。固定前缀后只替换最终断言的三条已验证案例，作为离线错误归因材料。

先在历史 8 个 B5 退步案例及确定性小表上检查每一步。再以每任务 20 条的开发试验测接口与实际效果，使用问题和原表特征分层抽样，记录数值、单位、比较、行域与多条件子群。固定样本后逐题配对，另冻结一批与已跑开发队列按表隔离的验证样本，供后续检验。WikiTQ 报告官方指称准确率，TabFact 报告准确率，FeTaQA 报告 BLEU、ROUGE-1/2/L。三任务都报告解析失败、非法引用、修复和完整失败成本。人工事实一致性作为待补指标。

## 实验二  条件保留的分块蒸馏

先重新审计 172 条旧轨迹和 192 条新增弱筛选轨迹。每条保存来源、原始操作链、可重放状态、归一化版本及条件验证结果。用相同来源分别生成各组监督记录。新增池上已有的离线结果为 777→764 个操作、0 个显式反馈标记、状态分块相对固定分块 token 代理成本下降约 0.23%。在扩大训练之前，先测真实多步题中有多少状态变化足以改变边界。

| 比较 | 固定项 | 检验点 |
|---|---|---|
| B0 与 B2 | 同原始样本、3B 底座、修复版训练 | 答案监督与完整操作链监督 |
| B2 与 B3 | 同执行接口、逐步调用 | 保留条件的链压缩 |
| B3 与 B5-fixed | 同压缩链与紧凑状态 | 逐步与固定分块 |
| B5-fixed、B5-blind 与 B5-state | 同压缩链、块长上限、操作预算及反馈边界 | 固定边界、忽略状态代价与考虑状态代价 |
| B4 与 B5 | 同训练轨迹、同分块策略 | 完整历史与紧凑状态 |

压缩允许删除经同表重放验证的冗余操作，保留条件绑定、反馈边界、原始答案和来源签名。实现从 `tableqa/optimization.py` 与 `verify_condition_rewrite` 扩展。用已知语义的小表反事实检验误删条件，例如给筛选阈值两侧补真实含义明确的行，并验证对应作用域。这些反事实用于机制诊断，真实队列沿用原表。

训练端分块目标为 \(\sum_{(i,j)\in\pi}[w_{in}L_{in}(S_i)+w_{out}L_{out}(a_{i:j})+\lambda_{call}]\)，带块长、生成长度和反馈边界约束。旧审计的调用代理常数为 128。新一轮先以同一 tokenizer 和同一提示冻结这些常量，分别报告等来源与等监督 token 控制，核对真实编码长度、训练曝光、有效步数和截断情况。显式平均梯度沿用已修复实现。在线由学生预测终止和分块，教师的完整轨迹只用于离线目标构造。需要执行反馈的边界依据当时是否已知下一步参数判断，不能从读写交集直接推出。

3B 先跑同源开发对照。若状态与忽略状态的监督边界基本一致，记录机制结果，优先补真实需要反馈的长链来源。形成可区分的监督目标后，再补核心配置三种子和等预算对照。WikiTQ、TabFact负责操作链蒸馏主比较。FeTaQA继续使用相同的官方答案监督支路，另做教师侧推理消融与跨任务迁移，独立报告支路成本和自动指标。取得审核条件后再补 FeTaQA 操作监督组。

## 正式对照与七类实验的落点

- **主实验和对比**分别汇报原源码 TabFact 复现和资源对齐比较。前者保留原版增列映射、100 行展示策略与候选数，并对同一题做有无映射配对。后者固定官方队列、模型与资源预算，保留各方法配置。分映射命中、未命中和实际调用增列三个口径。若拓展 WikiTQ/FeTaQA 的原版入口，单列任务适配结果。公开论文数值另列。
- **消融**采用实验一四组和实验二逐项对照。修复与可读证据作为独立开关，原证据负向试验进入机制材料。等来源、等目标 token 各有一套预算记录。
- **泛化**用冻结的未见表、跨主题和零目标训练样本协议，后续增加 32、128、512 条适应。预处理规则只由训练数据与开发阶段确定，同一规则迁移到目标集。
- **参数**在验证集单因素调整块长、LoRA rank、答案权重和修复次数。正式结果包含核心配置三随机种子，报告种子波动和题级配对区间。
- **机制与案例**同时呈现数值解析恢复、条件仍被遗漏、末端可恢复与不可恢复、分块边界变化和真实调用成本。使用固定规则抽取成功和失败案例。已有 8 个退步样本作为问题定位集，正式案例再按冻结规则抽取。

速度比较固定同一物理 GPU 或同一双卡配置、精度、后端、样本和生成预算。端到端计时包括预处理、条件生成、模型、执行、验证、修复及失败。模型时间已含修复生成时直接累计，另记后端异常尝试及未知 token。使用预热与重复测量，报告 P50、P95、生成次数和输入输出 token，并与任务准确率联报。开发诊断、训练成本和正式推理成本分表。

## 第一阶段实施记录

`run_chain_of_table_tabfact.py` 已支持 `--dater-map`。调用记录保存映射文件哈希、精确命中及文本变化。固定原版算子回放已验证命中和回退两条路径，规划与最终查询保留原句，增列首轮收到局部遮蔽后的文本。服务器 186 项测试全部通过。当前 TabFact 训练 92,283 条、验证 12,792 条，分别有 0 条精确原句命中。联合清理训练及验证队列的 TabFact 子集也均为 0。基线接入已验证，给定映射在现有开发队列上的清洗收益无法通过配对实测估计。

新增频率单位及显式小写别名后，两条历史失败块完成离线重放。处理器题使用 GHz 派生列执行原三项比较并得到标签 0。Cooper-Climax 题在完赛者的指定范围内排除 `Ret`，回放得到 Tony Maggs。两条均使用人工修改的操作块和末端读出。对历史预测及输入的哈希记录在 `preprocessing-replay.json`。
