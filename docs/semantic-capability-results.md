# 语义能力补齐：实现、诊断结果与训练候选

日期：2026-11-06。此阶段用于定位接口和工具使用问题，不是论文正式主实验。正式测试集与已经使用的确认集没有用于新增选型。

## 1. 已实现的范围

semantic_columns.py提供三种有界抽取：非嵌套括号字段、显式分隔字段、完整名次数字。仅允许从当前源列取值，不执行模型生成的正则或代码。失败保留整表与异常，不自动删行。字符位置使用Python Unicode码点，终点不包含；每条记录标明位置属于当前源格，并附上根单元格lineage，避免将派生格偏移误称原格偏移。

每条派生记录满足value=source[start:end]，并采用Prov(derived)=Prov(source)。这保证复制关系可核验，不能证明选对语义字段；轨迹显式保留semantic_correctness=not_proven。if惰性分支只记录实际执行的抽取，未执行分支不会被审计器再次求值。

推理新增semantic_extract和tool_demonstrations开关，默认关闭。记录构建及状态分块DP使用相同提示并计算示例的token成本，防止训练、推理和代价估计不一致。B0/B1可以复用同一来源池而不启用操作提示。

代码入口：tableqa/semantic_columns.py、core.py、inference.py、distillation.py、optimization.py与CLI；测试覆盖真实来源、字符跨度、Unicode、缺失/嵌套结构、保留并列、不可变状态、参考答案隔离、惰性分支、训练提示及代价计数。

## 2. 固定训练诊断结果

scripts/semantic_capability_pilot.py按seed2032预先从训练集中抽取8张不同表格，WikiTQ和TabFact各4条，按名次/括号代码启发式分层。筛选读取公开问题和表格，不读取标签或预测。类别不是人工确认的工具必需性标注；例如含名次列的高尔夫表问题实际需要处理复合比分。

同一32B实例、相同8K输入/1536输出上限、最多8操作/1修复，逐样本轮换三组顺序，原表不改写、无回退。额外提示token照计；这不是正式速度实验。

|组别|WikiTQ官方算法端口|TabFact准确|全部执行成功|有抽取尝试的样本|成功提交抽取链|
|---|---:|---:|---:|---:|---:|
|plain原接口|2/4|3/4|5/8|0|0|
|tools加抽取说明|2/4|3/4|5/8|1|0|
|tools_demo加说明和合成示例|2/4|2/4|4/8|2|0|

WikiTQ采用现有官方v1.0.2算法的Python3语法端口及targetCanon，保留源码、预测与输入哈希。其内置弱匹配均为1/4，与官方端口2/4不同，正式引用上表数值时不得混用弱匹配。

结论：示例让部分输出尝试工具，但没有成功执行该工具链，也没有观察到准确率提升。不能只报告“工具采用率增加”；示例组新增一次失败的负结果必须保留。8表子集不支持总体优越性或统计显著性结论，也没有包含Chain-of-Table原算法对照。

## 3. 已识别的过程问题

- 复合比分“71 + 69 = 140”：模型按+分割后把“69 = 140”直接当数字；修复时又在不含=的第一段上强行分割。正确程序需要先保留等号前的两轮比分，再分割+并计算均值。
- 名次列含“—”：示例组先对整列进行ordinal抽取，遇到未知名次失败；第二次又试图在派生之后过滤“—”。工具前置条件必须在转换之前处理，而且删去未知值是否符合题目范围需要语义判断。
- 某些修复仍先删除回答列、使用不存在的算子或错误聚合。这支持增加操作语法、数据范围和前置条件训练，不能单靠提示长度解决。

这些是训练集开发中的错误分析。依据这些样本开发后，不能把它们重新称为独立确认集或无偏总体测试。

## 4. 独立构造的训练候选

scripts/build_tool_curriculum.py已生成96条明确标为synthetic的训练样本和208条B5记录，六个模板各16条：括号代码计数、带未知值的名次范围、两轮比分均值、混合单位极值、跨行差值、全称量词的范围检查。WikiTQ格式64条、TabFact格式32条，后者标签16/16。

参考答案先由独立的生成变量计算，再与程序执行核对；不以程序自己的输出充当唯一真值。所有题目/表格由模板构造，不读取真实基准问题或答案；实际基准的失败类型用于选择训练技能，因此它仍是开发驱动的工程改进，不是独立发现的泛化证据。

其重要顺序包括：明确范围过滤→解析转换→聚合/比较→可执行断言。对“所有BLUE记录都大于阈值”，检查违反条件的BLUE记录数是否为0，不能用存在一个满足项替代全称判断。并列极值保留所有结果。

该池尚未自动合并、未据此宣布模型变好。继续训练前需要：

1. 保存模板/来源标记，合成结果不能填进真实测试表。
2. 两组从同一学生检查点开始、使用相同工具提示；对照组额外训练真实训练池，实验组加入合成技能材料。报告原始/实际来源、目标token、输入token、步数与重复曝光，区分数据增强和多训练量收益。
3. 同时检查代表性的旧开发集和预定义能力集；不能只在模板同分布问题上验收。
4. 若出现真实任务退化，降低合成比例或不采用该方案；保留结果。新方法/超参数冻结后才进入最终正式测试。

本机候选池：runs/tool-curriculum-v1；诊断及官方端口分数：runs/semantic-capability/results。服务器原始诊断冻结在runs/semantic-capability-v1/code与results，后续代码更新不得覆盖这一快照。

服务器已用真实3B tokenizer完成CPU预检：208原始记录，coverage平衡后224条，无预算裁剪、无对齐填充、保留全部96来源；每epoch监督15810 token（block12967、answer2843），最长完整记录1822 token。预检不加载模型权重，不执行训练。candidate-training-config.json指定原149来源B5适配器作为可选起点，不表示该训练或模型采用已经发生；比较设计冻结前不要直接将合成池收益归因给条件约束创新。

## 5. 原创性与基线边界

固定源码核验发现原Chain-of-Table已实现新增列的整列子串检查和受限操作顺序；抽取/子串校验/顺序限制均不单列为本文首创。详见[复现核验](chain-of-table-reproduction-audit.md)。本轮工具是能力补齐，论文候选贡献继续围绕问题条件显式绑定、跨步骤义务保护和条件保持的分块蒸馏。
