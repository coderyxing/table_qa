# 六项代码审查的处理记录

本次修复针对当前项目源码，历史运行通过各自的冻结源码、配置和预测文件追溯。

| 问题 | 核对与处理 |
|---|---|
| 探查 ID 覆盖 | LongTable 每次成功探查分配 probe_1、probe_2 等独立 ID，向模型反馈实际 ID。旧 probe 引用只在恰有一次探查时可解析，多次探查后报引用错误。当前正式 L4 协议仍保留最多一次探查、五次调用的预算 |
| 缺失人工审核 | 报告 missing_reviews、without_first_candidate、review_coverage 和 review_complete。审核不完整时，正式过程指标及二阶复核触发值为 null，已审核子集的指标单独放在 reviewed_subset_rates。自动答案分数继续使用完整题目集合 |
| Manifest 参数冲突 | 实际代码仅将 settings 子字典传入 Settings，implementation 与 ablation 位于外层。新增回归检查验证完整清单、参数扫描及未知参数报错行为 |
| 重试上下文增长 | 修复请求保留初始状态，将反馈写入用户 JSON，错误说明最多 512 字符。多次修复替换反馈，失败输出继续保留在 responses。提示版本升级为 tableqa-v6 |
| 数值列脏数据 | 增加显式 invalid_number=skip，跳过无法转成数字的单元格。默认 error，或先用 is_number 明确筛选。错误比较常量继续报错，合法零值参与计算 |
| 配对数据泄露 | 保留已有表 ID 与表指纹检查，对题面额外做 Unicode NFKC、大小写、空白和末尾常见标点归一化。源题和配对变体使用同一规则。表指纹仍负责识别相同原表上的改写题 |

引文定位修复与本次修改分属不同版本。后续对照应统一使用冻结的执行器和提示版本，核对监督记录重放及线上提示的一致性。独立探查 ID、精简重试反馈和显式脏数值策略均可能改变模型输入或执行结果。

新增回归用例位于 tests/test_review_regressions.py。覆盖连续两列探查、含缺失项的审核、清单元数据、长失败输出后的重试、脏数值与错误常量，以及跨划分同表和标点变化。

## 后续检查与中文注释整理

- API 后端现已透传 max_new_tokens，避免配置中的生成预算被默认值覆盖。
- 缓存临时文件使用进程 ID 与独立随机后缀。Windows 并发替换目标受限时，核对已有完整缓存后保留已写入的结果，清理当前临时文件。
- 后端异常的生成尝试计入 model_calls 和 model_seconds，无法得知的 token 用量记录为 null。
- 数值比较常量在遍历原表行前校验，空表同样拒绝错误常量。

中文注释覆盖 tableqa、scripts、tests 下的 128 个 Python 文件和 25 个 Shell 文件。文件级说明登记职责与使用方式，类和函数说明解释输入、返回形式及约束，核心路径补充状态提交、来源传播、预算、损失掩码和并发提交的原因。JSON 字段说明见 configs/README.md。

注释整理前后逐文件比较 Python 语法树，并对 Shell 执行 bash -n。最终单元测试共 203 项，199 项通过、4 项因可选依赖跳过。当前源码与历史服务器快照分别保留版本关系。
